# V7 平衡與連續四步重訓

2026-10-25 建立獨立實驗。V6 的累計 20,000 次、權重、影片與來源全部保留；V7 是新的實驗計數，最多另 20,000 次，6,144 envs。依使用者最新要求改為 6,144 envs，仍排在 wheel 之後；尚未有新訓練成果或合格策略。

## 為何需要重訓

[四步錄影診斷](results/v6_20000_four_step_diagnostic.json) 使用 V6 20,000 次原始權重，要求左、右、左、右後回站立；實際第一個左閃在 2.74 秒終止，不能為了拍滿四步而隱藏重設或補動作。當時 root 高度 0.832 m、upright cosine 0.956，未觸發原高度 0.52 m／直立度 0.65 門檻；左腳踝俯仰連桿的接觸力約 133 N，觸發原非腳底接觸 25 N 終止。此感測器是連桿淨接觸，不足以單憑此值判定接觸另一端或已整個倒地。

[獨立 32 回合四步／走路基準](results/v6_20000_four_step_baseline.json)，seed 42，每回合 20 秒，首次終止與後續 reset 資料都不算存活成果：

| 任務 | 存活 |
|---|---:|
| 左右左右四步及回站 | 0/8 |
| 右左右左四步及回站 | 0/8 |
| 前進後停止 | 7/8 |
| 站立 | 8/8 |

以上四步指四次交替閃身，不代表已完成四個普通步行步態週期。

## 新架構

保持原 DirectRLEnv、23 actions／110 observations、原生 CAD、PD、速度／扭矩限制、禁止接觸與終止門檻，另加 `BalanceLegEnv` 子類別。新檔案不修改已凍結的 V6 程式。

- 量測原生各剛體質量、質心位置與速度，計算質量加權全身 COM 與 capture point。
- 依實際承重腳底中心建立保守支撐膠囊距離成本。這只是漸進式 reward proxy，不是精確支撐多邊形證明或合格門檻。
- 加入軀幹／骨盆傾斜、失高、雙腳同時離地與實際非腳底接觸成本，保留既有真實卸載抬腳、接觸、滑動要求與失敗懲罰。
- 站立／恢復階段直接加入雙手回位成本；出手期間不以站姿手位壓制動作。
- 從第一輪就混合：50% 四步、20% 單側、20% 原方向控制混合課程、10% 站立。避免只因手部門檻而長期阻擋閃身練習。
- 在同一物理條件下比較舊 13115 與 V6 終點 actor 的原生四步存活率再選起點；只轉移完整 actor，critic、Adam、探索重新建立，不繼承任何驗收。
- 首段僅 10 次實際 PPO 作為 6,144 envs 的訓練路徑檢查，之後每 100／500 次保存並使用獨立種子驗測。
- 達四步／走路診斷存活門檻後才檢查原本完整上下身門檻。通過一份完整報告仍只是候選，不能跳過重複驗證與獨立確認，不能直接發布正式策略。
- 新更新至少 2,000 次後，最近五次四步存活率範圍小於 2 個百分點即停止待檢查；來源變更、工作程序錯誤、12 分鐘 worker 超時亦停止，不無限重試或放寬門檻。

## 目前執行狀態

已完成基準測試與五項 CPU 平衡成本測試。`q1-wheel-reference-training` 持有共用 GPU 訓練鎖，因此 `q1-leg-balance-v7-training` 等待佇列，尚未開始大規模 PPO 更新；不停止另一個專案的既有訓練。此狀態為文件提交時快照。

```bash
systemctl --user status q1-leg-balance-v7-training --no-pager
cat outputs/balance_v7_queue.json
cat outputs/balance_v7_status.json  # 取得共用佇列後建立
tail -n 40 outputs/balance_v7_supervisor.log
```

取得佇列後自動保存凍結來源快照與 SHA，先執行兩份 actor 的原生基準，再開始 PPO。輸出位於 `checkpoints/isaac/balance_v7/runs/balance_20261025/`，舊 V6 終點與正式網頁控制器不覆蓋。訓練中不修改凍結檔案；若出錯需先看該段 `native.log` 與 `worker_error.json`，保留計數與 checkpoint 再處理。
